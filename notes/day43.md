## 卡点与教训

| 卡在哪 | 性质 | 处理 |
|---|---|---|
| **`http` 只给了签名手册、没给可跑示例** | **我的账**（`net` 给了 echo 示例，`http` 没给）| 当场补 `mini-server.js`，他重打后自己发现"原来这样" |
| **"register/login 时建 session" 与 "register 不该建" 自相矛盾** | **我的账** | 已澄清：两种方案都行，但**建了 session 就必须下发 Cookie**，否则是死数据 |
| **讲义里两个 `Content-Length` 是我编的**（写 17/44，实为 13/38）| **我的账** | 他照抄没错；补正确算法：`Buffer.byteLength()`，中文 3 字节 |
| PowerShell 里 `curl` 是 `Invoke-WebRequest` 别名 | 环境坑 | 实测两种可用写法：Git Bash 的 curl / `Invoke-RestMethod` |
| 1/10 那次：**响应体是 mini-server 的格式** | 端口被 mini-server 占着 | `netstat -ano \| findstr :9001` → `taskkill //PID x //F` |
| `writeHead(409,'Content-Type','...')` | **API 签名**：第二参是状态消息 | 改成 `writeHead(status, headersObj)` |
| `req.headers.Set-Cookie` | 方向搞反：请求头叫 `cookie`（小写）| 讲清 `Set-Cookie`（响应）↔ `Cookie`（请求） |
| 方法检查放在字段校验后面 | 判据 10 用 GET 打 `/api/register` → 先命中 400 | **统一规则：先判方法 → 再校验字段 → 再查重 → 再写库** |
