## 四、10:00–12:00 边学边写：作用域链 + 暂时性死区

| 顺序 | 章节 | 覆盖今天的 | 时长 |
|---|---|---|---|
| 5 | [变量作用域，闭包](https://zh.javascript.info/closure) | **只读前半**：`代码块` → `嵌套函数` → `词法环境`（含 Step 1–3）→ `垃圾收集`。"Step 4. 返回函数"及之后的闭包任务**留到 Day 5** | 45 min |
| 6 | [var](https://zh.javascript.info/var) | `var` vs `let` 的差异、为什么现在只用 `let`/`const` | 20 min |

**顺带提个词对照**：javascript.info 不叫"作用域链"，它的说法是"首先搜索内部词法环境，然后搜索外部环境，以此类推，直到全局词法环境"——**这就是作用域链**，面试时两个说法都可能遇到。

### 今天必须能讲清的三件事

1. **作用域链**：内部函数找变量是由内向外逐层找，**找到就停**（所以内层同名变量会"遮住"外层的）。
2. **暂时性死区（TDZ）**：`let`/`const` 声明的变量，从代码块开始到声明语句执行之前，处于"死区"，访问会抛 `ReferenceError: Cannot access 'x' before initialization`——**不是**返回 `undefined`。原文：*"变量暂时无法使用的区域（从代码块的开始到 let）有时被称为'死区'"*。
3. **`var` 不会进死区**：`var` 因为提升，访问时得到 `undefined` 而不是报错——这就是 `var` 危险的根源之一。

### 写一个 `week1-language/day02-scope.js`

用 `console.log` 演示这三件事（自己写，别让 AI 代笔）：

- 一段能**让提升差异现形**的代码：同一个变量名，`var` 版本输出 `undefined`，`let` 版本抛 `ReferenceError`（用 `try/catch` 包住打印错误信息）；
- 一段**三层嵌套函数**，每层打印一个变量，注释写清这个变量来自哪一层；
- 循环里 `var` vs `let` 的经典差异（打印 3 次，看两次输出分别是什么）。

> javascript.info 那章末尾有个练习叫「变量可见吗？」，正好是这三件事的考题，做完再往下走。

### 2. `week1-language/day02-throttle.js` — 节流

需求：`throttle(fn, interval)`

- [ ] `interval` 内多次调用只执行一次
- [ ] **写两遍**："最后一次调用不补执行"和"最后一次调用补执行"各写一个版本，注释写清两种取舍的适用场景

### 3. `week1-language/day02-curry.js` — 柯里化

需求：`curry(fn)`，把 `f(a, b, c)` 变成 `f(a)(b)(c)`

- [ ] 支持任意参数个数：用 `fn.length` 判断参数收够了没有
- [ ] 边收边攒（`args` 累积），收够了才真正调用
- [ ] **陷阱题**：`fn.length` 对"带默认参数的函数"会返回什么？提示：默认参数**之后**的参数不计入 `length`。想清楚 `curry((a, b = 2, c) => {})` 会怎样，写进注释
- [ ] 顺手写一个 `compose`（今天的 LeetCode 正好用得上）

### 4. `week1-language/day02-clone.js` — 浅拷贝 vs 深克隆

- [ ] **浅拷贝三种写法**：`{...obj}` / `Object.assign({}, obj)` / 手写 `for...in` 循环，并**用代码证明**它们都只复制第一层（改嵌套对象会影响原对象）

- [ ] **和 `structuredClone()` 对比**：手写版少处理了什么？（`Date`、`Map`、`Set`、**循环引用**、函数）
- [ ] 用一段代码证明：`structuredClone` 能处理循环引用，手写版会栈溢出
- [ ] **把局限写进注释**：手写版不支持哪些类型
