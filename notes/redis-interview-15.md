# Redis 面试 15 问（A4 收尾口径，2026-11-28）

> 全部来自已学内容 + 我们本机实测。**每条 = 30 秒版答案 + 一个加分点 + 一个别踩的坑。**
> 背法：先背"30 秒版"的骨架（三条以内），加分点面试时再补，别一上来全倒。

---

## 1. Redis 为什么快？

**30 秒版**：三条 ——
① **纯内存操作**，不碰磁盘；
② **命令执行单线程** → 无锁、无上下文切换；
③ **多路 I/O 复用（epoll）**，一个线程盯很多连接。

**加分点**：还有**高效数据结构**（SDS、listpack、跳表、渐进式 rehash）—— 内存布局紧凑，cache 友好。

**别踩**：说"Redis 6.0 之后多线程了所以快" ✗ —— 多线程只是 IO，**命令执行还是单线程**。

---

## 2. 单线程为什么能扛高并发？6.0 的多线程是什么？

**30 秒版**：Redis 的瓶颈不在 CPU 而在**网络和内存**，单线程省掉了锁和上下文切换的开销；6.0 把 **socket 读写和协议解析**改成多线程，**命令执行仍是单线程**。

**加分点**：所以**"一个慢命令阻塞所有客户端"依然成立** —— 大 key、`KEYS`、慢 Lua 照样能让整个实例卡住。

**别踩**：以为"多线程了就不怕大 key" ✗。

---

## 3. 缓存和数据库的一致性怎么保证？

**30 秒版**：Cache Aside ——
- **读**：先读缓存，miss 读 DB 再回填；
- **写**：**先写 DB，再删缓存**（是**删**，不是更新）。

**为什么删而不是更新**：并发下"算出来的新值"可能比旧值还旧；**删掉让下次读自己去拉，天然幂等**。

**加分点**：删缓存可能失败 → **重试/消息补偿 + 短 TTL 兜底**（双保险）。

**别踩**："先删缓存再写 DB" —— 中间有读请求会把**旧值回填**，而且**没有下一次删除** → 永久不一致。

---

## 4. 缓存穿透 / 击穿 / 雪崩 分别是什么？怎么防？

**30 秒版**（三个必须分开答）：

| | 数据在 DB 里 | 触发条件 | 解法 |
|---|---|---|---|
| **穿透** | **不存在** | 每次请求都打到 DB | **缓存空对象** / **布隆过滤器** |
| **击穿** | 存在 | **单个热点 key 过期瞬间** | **互斥锁** / **逻辑过期** |
| **雪崩** | 存在 | **大批 key 同时过期** 或 **缓存服务整体挂** | **TTL 打散** / 高可用 / **熔断降级** |

**加分点**：
- 穿透：**随机 id 攻击用布隆**（内存固定）；**可控少量 id 用缓存空对象**（能记录被刷了哪些），但**空对象在随机攻击下会撑爆内存**。
- 击穿：**选互斥锁还是逻辑过期，看"重建耗时"** —— <100ms 用互斥锁，>1s 用逻辑过期（否则 3000 QPS 全排队）。
- 雪崩：**`TTL + random(0,5min)` 一行代码治 80%**。

**别踩**：把击穿和雪崩混着说；雪崩只说"同时过期"（漏了"服务挂"）。

## 5. 大 key 有什么危害？怎么发现、怎么处理？

**30 秒版**：
- **危害**：单次操作阻塞整个实例、打爆客户端输出缓冲区、集群迁移变慢；
- **发现**：`redis-cli --bigkeys`、`MEMORY USAGE key`、`SLOWLOG`；
- **处理**：**拆**（hash 分桶）、压缩、**用 `UNLINK` 异步删**。

**加分点**：`DEL` 大 key 是**同步释放内存**，几百 MB 能卡几秒；`UNLINK` 交给后台线程。

**别踩**：只答"删掉" —— 大 key 往往不能删，要**拆**。

---

## 6. `keys *` 为什么禁用？替代方案有什么坑？

**30 秒版**：`KEYS` 是 **O(N) 全表扫 + 单线程** → 几百万 key 能把 Redis 卡几百毫秒。**替代是 `SCAN`**（游标分批，不阻塞）。

**加分点（两个坑）**：
① **`SCAN` 不保证不重复** —— 扩容/缩容（迁槽）期间同一个 key 可能被返回两次 → 要自己去重；
② **集群下 `SCAN` 只扫本节点** → 要遍历所有 master 再合并。

**别踩**：说"用 `SCAN` 就完全等价于 `KEYS`" ✗。

---

## 7. RDB 和 AOF 怎么选？各丢多少数据？

**30 秒版**：

| | 格式 | **丢多少** | 恢复速度 | 文件大小 |
|---|---|---|---|---|
| **RDB** | 快照（某一刻状态） | **丢一轮**（最长 `save` 间隔） | **快**（直接 load） | 小 |
| **AOF** | 命令流（发生过什么） | **`everysec` 最多 1 秒** | 慢（逐条重放） | 大 |

**判据**：**"能容忍丢多久"** —— 能丢几分钟用 RDB；最多丢 1 秒用 AOF。

**加分点**：生产默认 **AOF + `everysec` + 混合持久化**（`aof-use-rdb-preamble yes`：base 用 RDB 格式为了加载快，incr 用 AOF 补增量）。**重启时有 AOF 就只读 AOF**。

**别踩**：用"哪个更先进/更安全"当判据 ✗ —— **判据是丢数窗口**。

---

## 8. AOF 重写期间的新写入会不会丢？

**30 秒版**：不会 ——
① fork 子进程按当前内存生成新 AOF；
② 期间父进程把写命令**同时**写到 `aof_buf` 和 **`aof_rewrite_buf`**；
③ 子进程写完后，父进程把 `aof_rewrite_buf` **追加到新 AOF 末尾**；
④ **`rename` 原子替换**。

**加分点**：**少了第 ③ 步就会丢"重写期间那几十秒"的写入** —— 这是重写机制里最容易答漏的一步。

**别踩**：只说"fork 子进程重写"，不提重写缓冲区。

## 9. 全量复制和部分复制？什么情况退化成全量？

**30 秒版**：
- **全量**：从库 `PSYNC ? -1` → 主库 `+FULLRESYNC <replid> <offset>` → 主库 `BGSAVE` → 传 RDB（期间写入进复制缓冲区）→ **从库先 `FLUSHALL` 再加载** → 补发积压；
- **部分**：从库 `PSYNC <replid> <offset>` → 主库 `+CONTINUE`。
- **三要素**：`offset` / `replid` / **`repl-backlog`**。

**退化成全量的四种**：① 第一次建立复制 ② 主库重启（replid 变了）③ **offset 已被挤出 backlog** ④ 从库重启（内存空了）。

**加分点**：`repl-backlog-size` 要按 **"写入速率 × 允许断线时长"** 估；1MB 在高写入下几秒就被冲掉。

**别踩**：漏掉"从库先 `FLUSHALL`"这一步。

## 10. 哨兵怎么选主？为什么必须奇数个？

**30 秒版**：
① 单个哨兵超过 `down-after-milliseconds` 没回应 → **`+sdown`（主观下线）**；
② 达到 **quorum** 票 → **`+odown`（客观下线）**；
③ **选举领头哨兵：需要多数票（N/2+1）**；
④ 领头哨兵**选从库**：`replica-priority` 最小 → offset 最大（数据最新）→ runid 最小；
⑤ 给从库发 `REPLICAOF NO ONE` → 其他从库改嫁 → 广播 `+switch-master`。

**为什么奇数**：偶数会出现 **N/2 : N/2 平票**，无法产生多数 → 切换卡住。奇数保证多数永远存在。

**加分点**：**`quorum` 是"判下线"的票数，不是"选主"的票数** —— 两者是两回事。
**旧主重启前必须确认切换已稳定**，否则那段时间它仍以 master 身份接受写 → 数据被新主覆盖后**永久丢失**。

**别踩**："选领主要全票" ✗（是多数票）。

## 11. 集群为什么是 16384 个槽？hash tag 干嘛用？

**30 秒版**：
- **`slot = CRC16(key) % 16384`**；
- **为什么 16384**：每个节点用 **bitmap** 记录"我负责哪些槽"，16384 bit = **2KB**；如果 65536 就是 **8KB**，而**心跳每秒都在发** → 带宽翻 4 倍。所以 16384 是"支持足够多节点"和"心跳包别太大"的折中。
- **hash tag**：`{order:1001}:items` —— 只对 `{}` 内的内容做 hash，让需要一起操作的 key **落同一个槽**，否则 `MGET`/事务/Lua 都报 `CROSSSLOT`。

**加分点**：**hash tag 要放 id，不是放类型名** —— `{order}:1001:items` 会让**所有订单挤同一个槽**，分片白做。

**别踩**：集群里 `KEYS`/`DBSIZE` **只看本节点**，不是全集群。

## 12. `MOVED` 和 `ASK` 的区别？

**30 秒版**：

| | 含义 | 客户端要做什么 |
|---|---|---|
| **`MOVED`** | 这个槽**永久**不归我了 | **永久更新本地槽映射**，以后都发新节点 |
| **`ASK`** | **迁槽进行中**，这个 key 已搬走但槽还没交割 | **只这一次**去新节点，**不改映射**；而且**必须先发一条 `ASKING`** |

**加分点**：**`ASKING` 只对下一条命令有效** —— 因为槽在目标节点上还是 `IMPORTING` 状态（官方归属还在源节点），不发 `ASKING` 会被拒绝或再踢回来。

**别踩**：把两者都说成"重定向到新节点"就完事。

## 13. 内存满了会怎样？

**30 秒版**：由 `maxmemory` + `maxmemory-policy` 决定，**8 种策略**：
- **`noeviction`（默认）**：**谁也不淘汰** → **写命令报 `OOM command not allowed`**，但**读正常、`DEL` 正常**（删除不增加内存）；
- **`allkeys-*`**：在所有 key 里挑（`lru` / `lfu` / `random`）；
- **`volatile-*`**：只在**设了 TTL** 的 key 里挑（`lru` / `lfu` / `ttl` / `random`）。

**加分点**：
- ⚠️ **`volatile-lru` 但所有 key 都没 TTL → 策略失效 → 照样报错**（这是最隐蔽的坑）；
- **LRU/LFU 都是"近似"**（`maxmemory-samples` 采样，默认 5），所以**可能误淘汰其实还很热的 key**；
- **一条写命令可能淘汰多个 key**（一直淘汰到低于 `maxmemory` 才停）。

**别踩**："内存满了 Redis 会自动删最旧的" —— 默认是 `noeviction`，**不删，只报错**。

## 14. 用 Redis 做分布式锁怎么做？

**30 秒版**：
- **加锁**：`SET lock:<key> <token> NX EX 5`（`NX` = 不存在才设，`EX` = 自动过期防死锁）；
- **解锁**：**必须用 Lua** —— 先比 token 再删（"读+比较+删"要原子）。

**为什么需要 token**：锁可能因 TTL 过期被别人拿到；**旧持有者醒来不能删新持有者的锁**。

**加分点**：
- 业务超时 → 需要"看门狗"续期；
- 单实例锁在**主从切换**时可能失效（主库写完没同步就挂了，从库上没有这把锁）→ 所以有 **Redlock** 之争（了解即可）。

**别踩**：解锁只写 `DEL lock:key` ✗ —— 会删掉别人的锁。

## 15. 线上 Redis 变慢，你怎么排查？

**30 秒版（分层，先分三堆）**：

| 现象 | 结论 | 查什么 |
|---|---|---|
| **`SLOWLOG` 有慢命令** | **服务端内在** | 改 API（`SCAN` 替 `KEYS`）、拆大 key、`UNLINK` |
| **`SLOWLOG` 干净但客户端慢** | **不是 Redis 的问题** | `--intrinsic-latency` 高 → **机器**（CPU 竞争 / **swap**）；低而 `--latency` 高 → **网络** |
| **`blocked_clients > 0`** | 有人在阻塞 | `BLPOP`/`XREAD BLOCK`，看是不是忘了设超时 |

**再往下三个指标**：
- `latest_fork_usec` 高 → fork 卡（内存大，第 5 章）
- `aof_delayed_fsync` 在涨 → **AOF fsync 卡住主线程**
- `INFO clients` 的 `omem` → **客户端输出缓冲区积压**（慢客户端）

**加分点**：**`rss ≫ used` 是碎片不是 swap；`rss < used` 才是 swap** —— 这个方向很多人说反。

**别踩**：一上来就说"加机器/升级配置"。

## 附：三个"一句判据"（面试官最爱追问的）

1. **"能容忍丢多久"** → 决定 RDB / AOF
2. **"重建耗时多长"** → 决定互斥锁 / 逻辑过期
3. **"结果可不可共享"** → 决定"请求合并（single flight）"还是"真互斥"（扣库存不能用合并）
