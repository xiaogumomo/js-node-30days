## 二、卡点与教训

| 卡在哪 | 性质 | 处理 |
|---|---|---|
| **`total_credits` 写成表函数** | **"修到不报错"就停** —— 他想要"一个数"，做成了 `RETURNS TABLE`，`SELECT total_credits(99)` 返回 **0 行**而不是 **0** | 已讲清「标量 vs 表函数」：无匹配时前者返 `0`、后者返 `0 行` |
| **`RETURNS NUMERIC` + SELECT 两列** | 报错 `必须返回且仅返回一列` —— **报错极其准确，但他没顺着它想"我要的到底是什么"** | 已点明：报错是"列数不对"，不是"精度不对"（他改成了 `NUMERIC(10,2)`） |
| **`TBALE` 拼成 `TBALE`** | 拼写族 | — |
| **`grade_check` 的 `ELSIF p < 60`** | **`IF` 链最后一个分支用反向条件 → NULL 会掉出去**。实测传 `NULL` → `控制流程到达函数末尾，但未执行 RETURN` | 已讲三层修法（最差 / `ELSE` 兜底 / 开头显式判 `NULL`） |
| **`USING` 三连拼错** | `cousrses` / `cousrse_id` / `courses_id`；而且 `USING` 报错说"**在左边的表中不存在**"，**把方向引到左表**，真因是拼错 | 已讲：`USING` 要求两表同名列、结果只留一列；报错指向会误导 |
| **粘 SQL 到 PowerShell 会直接执行** | 他问的 | 已讲：**`psql` 看分号、PowerShell 看换行**（PS 5.1 无 bracketed paste） |
