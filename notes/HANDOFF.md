## 二、协作模式（最重要的部分）

### 每日循环

1. 学生说"帮我制定今天的计划" → AI 写**任务书**（`notes/dayNN-<topic>.md`）+ **日志模板**（`notes/dayNN.md`），并**更新计划书**
2. AI 写**验证脚手架**（读学生的实现文件，打印 `✅/❌` 并汇总）
3. 学生写实现 → **AI 实测**（跑脚手架、跑 `node --check`、抽段验证）→ 给逐行诊断
4. 学生改 → 再跑 → 直到脚手架全绿
5. **提交由学生自己做**（除非学生明确要求 AI 提交）

### 三条硬约定

1. **实现由学生写；测试可以由 AI 写**（学生计划书 §一 的红线原文："允许：让它写测试、写类型签名、写注释文档。不许让 AI 直接写出整个函数然后粘贴"）
2. **日志里学生写的内容不许删改** —— AI 的意见放在独立小节（`## AI 复核`）或 `>` 引用块里，并标明是 AI 补的
3. **AI 说的每个技术结论，先跑一遍再说** —— **已经犯过三次**（2026-10-05 又添两次）：
   - ① 我说"删掉 constructor 还是 4 行"，实测是 3 行；
   - ② **10/5**：我说 `const { path } = require('node:path')` "也能跑" ✗ —— **实测 `path` 是 `undefined`**（`node:path` 的导出里**没有** `path` 这个属性）→ 学生照着写 → `Cannot read properties of undefined (reading 'join')`；
   - ③ **10/5**：我给的修法写成"`WHERE uesrId = ?` ✗ → `userId` ✓"—— **没交代"改哪一部分、其余不动"**，而且**我写这条时引用的是"已经变过的那一行"**（没先读当前文件）→ 学生按它改出来的 SQL 丢了 `WHERE`，`uesrId` 变成了**表别名**（**合法语法，不报错**）→ **过滤条件消失 = 越权** ✓ 只有判据 `07` 抓得到。
   **⛔ 两条规矩（AI 也要守）**：① 给"改哪一处"的指令，必须写成"**把 X 换成 Y，其余照旧**"，**且一条只许含一处改动（两处=两条）** —— 10/8 我把"改名"和"包成箭头函数"塞进同一条 → 学生只改了一半、白跑一轮 ✓；② 写诊断 / 引用代码之前，**先读当前文件**（别用记忆或上一轮的行号）。
   - ④ **10/7（同一个错法第 4 次）**：学生修 `06` 那条漏网突变（M10）时，我把"改哪一处"写成"**把第 140、142 行的邮箱都加上 `@`**" ✗ —— 而 **140 行那条的用途恰恰是"测没有 @"**，照我说的改会**直接毁掉一条测试**。⭐ **学生指正了我**（"只改 142 就行了吧？"）✓ 对。**比这条错更该记的是判据原则**：**改测试数据前先问"这条测试的【唯一变量】是什么"** —— 一条测试只让**一个**东西错，否则它测的可能是别的规则（**M10 漏网就是这么来的**：`06` 第二条的邮箱也没 `@` → 被邮箱规则挡住 → 密码长度规则从没被考到）。
   ⭐ **学生 10/5 主动指正了 AI 的这条指令** —— 那正是 §六 附录 D 自检里"**能说清我的代码里哪部分是 AI 帮我写的、我怎么验证它的**"要的能力 ✓ **要表扬、要继续鼓励他这么干**。

## 三、错误类型演进与薄弱点

> 这一节是给下一个 AI 会话看的：**它决定"该给多少提示"**。写在这里是为了不用每次从零摸索。
> 对本人来说，这也是一份"我这一周的错误是怎么变的"的记录。

### 错误类型的演进 —— 这是最重要的诊断数据

| 阶段 | 错误类型 | 表现 |
|---|---|---|
| Day 4 `debounce` | **知识缺口** | `setTimeout` 没见过 → 直接卡死、无从下手 |
| Day 5 `throttle` 路线 B | **结构理解** | 代码放错位置（`return` 之后 / `if` 外面）→ 改 3 次 |
| Day 7 `myMap` | **手滑 / 不熟练** | 5 处 bug，**没有一处是"不懂"**（`>` 写成 `<`、`slice` 参数、`fn()` 没传参） |
| Day 7 零提示题 `dropNulls`（9/20） | **检索失败**（新类型） | 学过的 API 在"零提示"下取不出来：知识点 Day 3 排过、读过、清单打过勾，`for...in` 在 deepClone 里还用过 —— 零提示时却退化成"用数字下标 `obj[i]` 遍历对象" |

**结论：不懂的边界在收缩。** 当错误类型是"手滑"时，**给骨架不再有帮助** —— 需要的是"自己从零做一遍"。

**第三种类型（9/20 新增）：会，但取不出来。** 这是零提示题第一天就抓到的，也是最值得记的一条 —— 上面三种类型**要的介入方式完全不同**：

| 类型 | 表现 | 该怎么介入 |
|---|---|---|
| 知识缺口 | "这个我没见过" | 补章节（书单） |
| 结构理解 | "知道概念，但代码放错位置" | 改 + 讲解 |
| 手滑 | "都会，就是写错" | 让他自己重写，别给骨架 |
| **检索失败** | **"学过、用过，零提示下想不起来"** | **不讲概念、不给代码** —— 只指路到他自己的材料，然后要求"第二遍"（合上书）+ 隔一两天同类题再考 |
| **首次上手**（9/27 新增，`fetch` 那次）| **"今天第一次见，自己独立完成肯定不可能"** | **分块练**（把整件事拆成 3–4 块，每块亲手写一个能跑的东西）→ **隔一天**再合上重写整份 + 进轮转表。**⚠️ 不要整份"合上重写"** —— 那对他不公平，也测不出东西 |

**判断顺序（下次遇到卡点照这个走）**：① 书单排过没有？→ ② 排过的话，学过之后有没有留下**能跑的东西**？（查清单的勾对不应对得上活代码）→ ③ 都对得上还卡住，才是真的知识缺口。

## 九、环境事实速查（都已实测，省下重新试错的时间）

**项目 2 的技术选型（2026-10-05 实测，**别再重选**）**
- **数据层：`node:sqlite`（Node 24 内置，零依赖）** —— `new DatabaseSync(file)` / `db.exec(建表SQL)` / `db.prepare(...)` + `.run|get|all(参数)` ✓
  ⚠️ **`db.exec()` 不接受参数**（里头的 `?` 没人填 → 当 NULL；要带参数**必须** `prepare` + `run/get/all`）；**`prepare` 时会立刻校验表和列名**（列名拼错 → 启动就炸 ✓）
- **密码哈希：`node:crypto` 的 `scryptSync`**（随机盐 + `timingSafeEqual`）；**JWT 手写 HS256**（`createHmac` + `base64url`）→ **不装任何数据库 / 哈希 / JWT 依赖** ✓（bcrypt / argon2 在 Windows 上要编译，故意不用）
- 迁移：**简化版**（`PRAGMA table_info(tasks)` 先查再改 → 幂等 ✓）；数据文件 `data/tasks.db`（`.gitignore` 的 `*.db` 挡住 ✓）
- 三份判据（`server` / `tasks-crud` / `auth`）在 10/5 起**都要求先注册+登录拿 token**（判据内部自己做了 ✓）

**TypeScript / 工具链**
- `pnpm add -D typescript @types/node` —— **`@types/node` 必须装**，否则 `require` / `module` 报 `Cannot find name`。
- **判据/脚手架放在 `test/` 目录外，就不会被 `node --test` 自动发现**（9/24 实测：在仓库根跑 `node --test` 只找到工具箱那 **27** 条，`week2-runtime/*-verify.js` 不参与）→ 所以「把当天的判据提前写好」**不会**把全绿的套搞红；"别提前写测试"那条规矩只对 `test/` 目录成立。
- ⚠️ **`projects/*/test/` 会被自动发现**（9/26 起）→ **9/27 实测：仓库根 `node --test` 一共 45 条** = 工具箱 27 + `projects/p1-cli-organizer/test/cli.test.js` **9** + `test/apply.test.js` **9**（Day 14 才实现 `--apply`）；其中 **6 条红**（`apply.test.js` 里"还没实现的 `--apply`"那 6 条）—— **这是设计如此：判据就是待办清单**，不是环境坏了。**想查"工具箱基线"请用 `cd week1-language/p0-toolkit && pnpm test`（27 条全绿）。**
- ⚠️ **`test/` 目录里任意 `.js` 都会被 `node --test` 当成测试文件**（不只 `*.test.js`）→ 里面放非测试文件 = **多一条"幽灵通过"**（见 §三）。**规矩：`test/` 只放 `*.test.js`。**
- ⚠️ **`--max-old-space-size` 挡不住大字符串 / 大 Buffer**（9/27 实测）→ **不能用它当"流式"的判据**：64MB / 128MB 的文件在 16MB / 8MB 上限下照样跑通（V8 的大对象空间不认这个上限），只有 256MB 才崩。想验"有没有整份读进内存"，只能**看代码**。
- **TS 7.0.2 删掉了 `moduleResolution: "node"`**（报 `TS5108`）→ `tsconfig.json` 用 `module: "nodenext"` + `allowImportingTsExtensions: true` + `types: ["node"]`。
- `node 文件.ts` **能直接跑**（Node 24 类型剥离）；`node --test` **会自动发现 `*.test.ts`**；`require('../src/x.ts')` 也能用 → **不需要 Vitest / tsx**（Vitest 挪到第 3 周）。
- 递归函数报 `TS7023` / `TS7024` 时要**显式写返回类型**；"递归藏在回调里"才报，纯自递归 `return f(x)` 反而不报；断环写在外层或内层**任一**都行。
- ⚠️ **`package.json` 被追加过尾部垃圾**会报 `trailing characters at line 15 column 1` —— **看起来像源码文件的错**，实际杀 pnpm / tsc / Node 三件套。**JSON 只能有一个顶层 `{}`。**

**Git**
- 判断"推送成功"：`git ls-remote --heads origin main`（**直接问远程**，绕过本地缓存）和 `git rev-parse HEAD` 比 SHA。
- ⚠️ **`git add -A` 之前先 `git status`**：9/27 那份**放错目录的实现**（`projects/p1-cli-organizer/test/cli.js`）就是这么被扫进 `80ce96e` 的，结果"9/9"在仓库里**复现不出来**。**实现归 `src/`，判据归 `test/*.test.js`。**

**日历 / 时钟**
