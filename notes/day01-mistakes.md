## 三、错因聚类：5 个真问题 + 2 个习惯问题

### A. ToPrimitive（对象/数组 → 原始值）——**你的判断成立，这条确实不在主线书单里**

对应错题：Q12、Q13、Q14、Q21（Q20 也沾边）。

`day01-types.md` 指定的 5 节是：数据类型 / 类型转换 / 基础运算符 / 值的比较 / 对象引用和复制。这 5 节里**没有**"对象如何转成原始值"这一环，也**没有**"数组"这一章。我核对过：

- 《基础运算符》只讲"`+` 遇字符串就拼接"，没讲 `[]` 到底怎么变成字符串；
- 《对象 —— 原始值转换》这一章**不在你的书单里**，而它正是 `[] + {}` 这类题的钥匙；
- 数组转成 `'1,2,3'` 这件事写在《数组》一章的 `toString` 小节里（原文："数组有自己的 `toString` 方法的实现，会返回以逗号隔开的元素列表"，例子 `alert( arr ); // 1,2,3`）——这一章也不在书单里。

**要背下来的规则（一条顶四道题）：**

```
`+` 的两侧只要有一个是字符串 → 拼接
都不是字符串时 → 先做 ToPrimitive 转换，再看转换结果
  数组  → toString() → 元素用逗号连接       [1,2] → "1,2"   [] → ""
  对象  → toString() → "[object Object]"    {}    → "[object Object]"
  所以：[] + []  → "" + ""             = ""
        [] + {}  → "" + "[object Object]" = "[object Object]"
        [1,2]+[3]→ "1,2" + "3"        = "1,23"
```

### B. `+` 的结合方向 —— **你 Q16 答对，是"蒙对的"**

对应错题：Q15（Q16 名义上对，实则错）。

对比这两题：

```
Q16. '3' + 2 + 1   → 你写 '321'  ✅
Q15. 1 + 2 + '3'   → 你写 '123'  ❌（正确 '33'）
```

你答对 Q16、答错 Q15，不是巧合——说明你脑子里的规则是**"只要有字符串，整个表达式都当字符串拼"**。这条规则在 Q16 上恰好给出正确结果，在 Q15 上就暴露了。真正的规则是：

> `+` 是**从左到右**逐个结合的二元运算符，先算左边一对，把结果再和右边结合。

```
1 + 2 + '3'  →  (1+2) + '3'  →  3 + '3'  →  '33'
'3' + 2 + 1  →  ('3'+2) + 1  →  '32' + 1 →  '321'
```

**这一条比分数重要：答对的题也可能是"用错规则蒙对的"。以后每道答对的题也要问自己一句"我是靠哪条规则算出来的"。**

### C. `==` 不是"看左边右边像不像"，而是"能不能转成同一个原始值"

对应错题：Q20、Q21、Q22（加上 Q19，C 组 6 道你只稳了 2 道）。

这是你**失分最集中的一组**，也是这个计划里被点名"面试核心"的一组（`day01-types.md` 原话："Q21/Q22 是 `==` 和 `===` 差别的标准例证，务必能讲清"；周自测也点名了 `[] == false`）。

有一个很硬的证据：你 `notes/day01.md` 的"代码备忘"里亲手写了

```powershell
[] == false              # ?
```

——**这就是你答不出来的那一道题**。说明这行字是"抄下来"的，不是"想过"的。

完整链路（要能自己复述）：

```
[] == false
→ == 遇到类型不同 → 两边都转成数字
→ [] 走 ToPrimitive："" → Boolean 转数字：false → 0
→ Number("") === 0 ，0 == 0
→ true

[] === false
→ === 不做任何转换，类型是 object vs boolean
→ false
```

### C2. `NaN` —— 相等性对 NaN 不成立

Q19 你写 `true`。直觉是"一个东西当然等于它自己"，但规范把 `NaN` 定义成**不等于任何值，包括自身**。判断要用 `Number.isNaN(x)`（不是全局的 `isNaN()`，后者会先做类型转换）。

### D. `typeof` 的返回值是个**只有 8 种**的封闭集合 —— 你说"辨认能力弱"，根因说偏了

对应错题：Q3–Q7（A 组 8 道你空了 5 道）。

你的诊断是"对 `object`、`function` 这些的辨认能力弱"。更准确的说法是：**你记住了两条孤立事实（`typeof null === 'object'`、`typeof typeof 1 === 'string'`），但没有"typeof 的返回值只有 8 种"这个模型。**

`typeof` 的全部可能返回值，一个不多：

```
"undefined" | "object" | "boolean" | "number" | "bigint" | "string" | "symbol" | "function"
```

有了这个封闭集合，题目就不用背了，是推出来的：

- 所有引用类型（数组、`Date`、`Map`、正则、普通对象）**统一**是 `'object'` → Q5 答案直接推出；
- 唯一特判：可调用的东西（函数、箭头函数、`class`）→ `'function'` → Q4、Q7；
- 唯一 bug：`null` 也是 `'object'`（内存里全 0 表示，恰好匹配 object 标签）；
- `NaN` 属于 number → Q3；`10n` → `'bigint'` → Q6。

**注意 Q5 和 Q1 的关系**：Q1（`typeof null`）你答对了，Q5（`typeof []`）却空着——说明你手里是"一条条事实"，不是"一张网"。

### E. Q26 —— 这条**不是**知识盲区，你的诊断要推翻

你说的第 2 条是"`const` 用法主线未详细提及"。**这条不成立**，证据有三层：

1. `const` 本身写在 javascript.info 的《变量》一章，是基础知识；
2. 更关键：你书单里的**第 5 节《对象引用和复制》里就有一整节**，标题是——

   > **使用 const 声明的对象也是可以被修改的**

   它举的例子几乎和 Q26 一模一样：

   ```js
   const user = { name: "John" };
   user.name = "Pete";     // (*)
   alert(user.name);       // Pete
   ```

3. 而且**你自己的笔记 `day01-types.md` 的阅读表格里就写了**，第 5 节要覆盖"引用类型 vs 值类型、**为什么 `const` 对象能改属性**"。

所以真相是：**内容在书上，也在你自己写的书单里，但没进脑子。** 这是典型的"被动阅读"——读的时候每句都懂，合上书就答不出来。

（唯一值得同情的细节：这一节的小标题没有出现在页面右侧的目录导航里，顺着导航扫容易滑过去。）

**结论**：这条从"主线没讲"改写成"我需要一个『读完 → 合上书 → 自问自答』的验收动作"。
