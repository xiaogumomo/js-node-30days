## 二、产物是什么（这才是 A4 的交付）

| 函数 | 干什么 |
|---|---|
| `serializeEntry` / `deserializeEntry` | 逻辑过期的编解码（**值里带 `expireAt`**，不靠 Redis TTL） |
| **`getOrLoad(cache, key, loader, opts)`** | **核心**：命中 → 返回；过期 → **立刻返旧值 + 后台重建**（懒重建，`Map` 去重）；miss → **抢锁（token）→ loader → 回填**；没抢到 → **重读缓存**；等满 → 兜底 loader |
| `invalidate` | Cache Aside 的"删" |

**三个防护点全部落地**：**防穿透**（哨兵值）/ **防击穿**（互斥锁 + token）/ **逻辑过期**（不阻塞读）。

## 五、他今天三个概念提问（都问在点上）

| # | 问题 | 结论 |
|---|---|---|
| **1** | `loader` 是什么？ | 调用方传进来的"去数据源取数"的函数；**`getOrLoad` 里不该出现 SQL/HTTP**；它无参数（key 走闭包） |
| **2** | **兜底调 `loader()` 不是绕过互斥锁吗？** | **是的，绕过**。兜底只在"**锁塌了**（持有者死了、锁过期了还没人接手）"时才该开火 → 所以 `waitMs × maxWaitRounds ≥ lockTtlSec` |
| **3** | 没抢到锁的等待者，为什么能拿到持锁者的数据？这算分布式锁吗？ | **前半对**：数据的值只由 `key` 决定，谁查都一样。**后半要修**：**它仍然是分布式锁**，区别在**"结果可不可共享"** —— 扣库存不可共享（必须排队），缓存重建可共享（直接读）。这个模式叫 **Single Flight / 请求合并** |

**我补的安全坑**：**key 的粒度 = 数据的可见粒度**。`getOrLoad(cache, 'user:profile', ...)` 会把 A 的档案给 B —— **key 写错的后果不是"不命中"，是"串数据"**，比穿透严重。
