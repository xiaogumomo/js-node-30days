### ⑥ 主线：`week2-runtime/day11-ndjson.js`（90 分钟）

**目标**：读一个**大文件**（NDJSON —— 一行一个 JSON），逐行解析并统计，**并且实测"整读"和"流式"的内存差别**。

**接口（判据要用，名字必须对齐）**：

```js
// 导出一个函数，供判据直接调用
async function summarize(file) { ... }
module.exports = { summarize };

// 同时作为命令行脚本能直接跑：
//   node week2-runtime/day11-ndjson.js <文件>
```

**`summarize(file)` 要返回**（形状固定，判据按这个断言）：

```js
{
  lines: 6,      // 【有内容的行】数（纯空行不算）
  ok: 5,         // 能 JSON.parse 成功的行数
  bad: 1,        // 有内容但 parse 失败的行数   ← 恒等于 lines - ok
  bytes: 123     // 文件的字节数（stat.size；注意是字节不是字符）
}
```

**要求**：
1. **先写"整读版"**：`fs.readFile` 一次读进来 → 按 `\n` 切 → 逐行 `JSON.parse`（**先让它跑出数字**）
2. **再写"流式版"**：`createReadStream` + `readline` 逐行读（**不把整个文件读进内存**）
   - ⚠️ 两个坑：**最后一行可能没有换行符**（别漏）；**`\r\n` 的行尾**要处理掉再 parse
   - 进阶（时间够再做，否则顺延）：自己写一个 `Transform` 流来切行（`readline` 本质上就是内置的"帮你切行的 Transform"）
3. **坏行不能让程序崩**：`JSON.parse` 抛错要**计数**（`bad++`），继续读下一行
4. **`bytes` 用字节**：`stat.size`，别用字符串长度（中文是 3 字节/字）
5. **命令行入口**：`process.argv[2]` 是文件路径；还能 `--json` 输出 JSON
6. **文件不存在**要**友好报错**（一句人话 + `process.exitCode = 1`，不是崩一堆栈）
7. **CLI 入口要能被安全 `require`**：包进 `if (require.main === module) { ... }`（昨天判据的 00/08 就是查这个的）
8. **内存实测**（今天的核心证据）：
   - 先生成一个大文件 —— 写个临时脚本或在 REPL 里循环写，目标 **几十 MB**（比如 20 万行 `{"id":1234,"name":"..."}`）
   - 两个版本各跑一次，打印/记录 **`process.memoryUsage().heapUsed` 的峰值**（可以每读 N 行采样取最大）
   - **期望看到的**：整读版的峰值**随文件大小上升**（≈ 文件大小量级）；流式版**基本与文件大小无关**
   - 可选加分：用 `node --max-old-space-size=64 文件` 跑两个版本对比（整读版可能直接挂，流式版应该活着）

**跑起来才算数**：
```powershell
node week2-runtime/day11-ndjson.js 某个.ndjson            # 人看的三个数字
node week2-runtime/day11-ndjson.js 某个.ndjson --json     # 纯 JSON
node week2-runtime/day11-ndjson.js 不存在的文件            # 期望：友好报错
```

**做法建议**：整读版先跑出数字 → 再改成流式版 → **两个版本的输出必须一模一样**（用同一个大文件对一次）→ 最后量内存。**每加一步跑一次。**
