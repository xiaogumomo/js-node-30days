## 三、⭐ 今天最重的一条：**RESP3 把"订阅连接不能发普通命令"推翻了**

他做 PubSub 时在 `sub` 连接上 `SET`，**返回 `OK`** —— 和我教的"订阅后不能发普通命令"冲突。

**查证（源码 + `CLIENT INFO`）**：

```

```

| 协议 | 订阅连接能否发普通命令 | 证据 |
|---|---|---|
| **RESP2** | ❌ | `redis-cli`：`ERR Can't execute 'set': only (P\|S)SUBSCRIBE / … allowed in this context` |
| **RESP3** | ✅ | 他的 `OK`；我复现也是 `OK` |

**两层报错还长得不一样**：
- **RESP2 + ioredis**：`Connection in subscriber mode, only subscriber commands may be used` ← **客户端自己拦**（`built/Redis.js:365`，命令没发出去）
- **RESP2 + redis-cli**：`ERR Can't execute 'set': …` ← **服务端拦**

→ **我的错（第 4 次同族）**：**把"限制类规则"当成绝对真理，没标协议前提**（同 11/21 那个"不监听 error 会崩"）。

## 四、`duplicate()` 完整讲法（他要求的"参数属性和延伸"）

**源码只有一行**：`duplicate(o) { return new Redis({ ...this.options, ...(o ?? {}) }) }` → **同步返回 / 浅拷贝 / override 只影响新连接**。

**实测继承表**：

| 项 | 继承？ | 实测 |
|---|---|---|
| `db` / `keyPrefix` / `protocol` / `retryStrategy` | ✅ | `db:2`、`pf:`、`3` |
| ⚠️ **`lazyConnect`** | ✅ **是坑** | 新连接 `status='wait'`，**得自己 `connect()`** |
| ❌ **事件监听器** | **不继承** | 原 1 个 → 新 **0** 个（`listenerCount`） |
| ❌ **`defineCommand()` 注册的命令** | **不继承** | `typeof d.foo === 'undefined'` |
| ✅ `{ scripts: {...} }` 构造参数 | 继承 | 构造函数里有 `if (this.options.scripts)` |

→ **`defineCommand` 是把命令挂到实例上，不写回 `options.scripts`**；要跟着走必须用构造参数 `scripts`。
→ **`Redis.Cluster.duplicate(overrideStartupNodes?, overrideOptions?)` 签名不同**（第一个参数是节点列表）。

## 八、⭐ 今天挖出来的新东西

### ① 7.0 双 ID 现场（他抓到的）

```
提升后：master_replid:9bf53eb0…（新的）  master_replid2:b1dc69a9…（旧主的！）  second_repl_offset:11198
改嫁回：master_replid2 变回全 0，second_repl_offset 变回 -1
```

**意义**：旧主的其他从库拿旧 replid 来连新主 → 认得 → **部分复制，不搞全量**。没有它，每次故障切换都会引发**所有从库全量**（复制风暴）。

### ② `sync_partial_err:1` —— 把 §6.3.4 的三要素串起来

```
主库 INFO stats → sync_full:2  sync_partial_ok:0  sync_partial_err:1
```
他 4.5 改嫁时：从库带着**被提升后的新 replid**（`9bf53eb…`）去 `PSYNC` → 主库不认识 → **部分复制失败（err+1）→ 退回全量（full+1）**。

### ③ `clients_in_timeout_table` 能区分"有没有超时"

他说"看不出 BLPOP 阻塞了多久"。我实测（两个客户端，一个 5 秒一个 0）：

| 场景 | `blocked_clients` | `clients_in_timeout_table` |
|---|---|---|
| `BLPOP k 5` | 1 | **1** |
| `BLPOP k 0` | 1 | **0** |

→ **`blocked=1` 但 `in_timeout_table=0` = 永不过期**。他贴的正是 `0`。

### ④ `SLOWLOG` 会被 `REPLCONF ACK` 灌满

阈值设 0 之后，128 条槽位**几乎全被从库每秒一条的 `REPLCONF ACK`（2–3µs）占满**。
→ **阈值 0 只能短时用**；**慢查询日志会记录内部命令**（`REPLCONF`/`PING`/过期循环），排查要会过滤。
