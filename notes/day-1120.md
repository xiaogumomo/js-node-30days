## 四、我在今天的判据上错了三次（他都抓到了）

| # | 我的错 | 正确 |
|---|---|---|
| 1 | 写「`LMOVE ... RIGHT LEFT` 返回 **`t1`**」 | **`t3`**（`RIGHT` 从源右边取 = 最后 `RPUSH` 进去的） |
| 2 | 更深的问题：**没指出 `RIGHT` 是"栈"的取法** | **队列要用 `LMOVE ... LEFT LEFT`**（取最老的） |
| 3 | 写「`SET` + 三次 `INCR` → 打印 `1 2 3 4`」 | **`OK` / `2` / `3` / `4`**（`SET 1` 后第一次 `INCR` 就是 2） |

**另外一处习惯问题（我提的）**：他的 `redis.on('ready')` 是**碰巧**抓到的（连接在下一个 tick 才建立）。生产里如果前面 await 了别的东西，`ready` 早触发完 → **监听器永远收不到**。正解：`if (redis.status === 'ready')` 或用 `once`，或干脆 `await redis.ping()` 探活。

## 五、今天三个"反直觉"（他的判据题的产物）

| # | 反直觉 | 真相 |
|---|---|---|
| 1 | `>` = "未 ack 的消息" | **`>` = 按组进度投新消息**（跟 ack 无关）；**未 ack 的要用具体 ID 读**（读自己的 PEL） |
| 2 | `XACK` 会删消息 | **不删，只把消息从 PEL 移除** —— 所以 Stream 能重放；删消息要 `XDEL` / `MAXLEN` |
| 3 | `MAXLEN ~ 5` 会裁到 5 条 | **按压缩节点裁**，不在条数上精确 —— 节点没满就一条都不砍 |

**证据（都是他亲手跑的）**：

```
XADD lab:stream → 1795139749747-0
XREADGROUP g1 consumer_a ... > → 第 1 条
XREADGROUP g1 consumer_b ... > → 第 2 条        ← 组内不重复
XPENDING → 2 条；XACK 一条 → 1 条
XCLAIM ... consumer_c 0 <id> → 投递次数 1 → 2   ← at-least-once 的现场证据

XLEN lab:trim（MAXLEN ~ 5 塞 10 条）→ 10       ← 近似裁剪没触发
XTRIM lab:trim MAXLEN 5 → 5                    ← 精确裁剪立刻生效
```

## 七、Node 层的新知识（第一次，所以记细）

### `ioredis` 四种连接写法（都实测可用）

```js
new Redis()                                    // 默认 127.0.0.1:6379
new Redis(6379, '127.0.0.1')                   // 端口, 主机（顺序有容错）
new Redis('redis://127.0.0.1:6379')            // URI（和 p2 的 DATABASE_URL 同族）
new Redis({ host: '127.0.0.1', port: 6379 })   // 对象 ← 推荐
```

### 三条与 `redis-cli` 不同的地方

| # | redis-cli | Node |
|---|---|---|
| 1 | `(nil)` | **`null`** |
| 2 | `INCR` 显示 `(integer) 2` | **返回数字 `2`**；但 `GET` 返回 **字符串 `'2'`** |
| 3 | `(error)` 打印 | **抛异常** → 必须 `try/catch` |

### `ioredis` 的返回形状（实测）

| 命令 | 返回结构 |
|---|---|
| `XRANGE` | `[[id, [f,v,...]], ...]`（**2 级**） |
| **`XREADGROUP`** | `[[streamKey, [[id, [f,v,...]]]], ...]`（**3 级**，多一层"哪个 stream"） |
| **`XPENDING`（汇总）** | `[count, minId, maxId, [[consumer, countStr]]]` |
| **`XPENDING` 空时** | **`[0, null, null, null]`** ← **不是 `[]`**，判空要用 `res[0] === 0` |
