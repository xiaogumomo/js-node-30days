## 今天两次被叫停（**都成立，都比知识点更重**）

### ① 「参考文档 ≠ 教材」

> "**知识点间毫无关系（就比如1.2和1.3，突然像是从一块跳到另一块）……看文档是查看知识点是否正确，而不是学习用的。从中我学习不到如何能让我从零开始配置PG的学习顺序感，这是我最绝望的。**"

**病根**：我照抄了 PG 官方文档第 19 章的小节序 —— 而那一章是按「**参数管什么资源**」排的（连接/资源/WAL/查询调优/日志/统计/autovacuum/锁/兼容性…），是**字典序**。字典序能回答"这个参数什么意思"，**永远回答不了"我下一步学什么"**。

**改法**：学习序 = **因果链**
```
客户端怎么连（2.3）→ 参数在哪几个文件（2.4.1）→ 哪几项决定听不听得见（listen_addresses/port）
→ 准不准进（pg_hba 五字段+匹配顺序）→ 进来是什么身份（8.1 角色）→ 身份能干什么（8.2 GRANT）→ 从库怎么连主库（第11章）
```

### ② 「他一直用 ≠ 他会」

> "**`docker exec pg-a3 psql -U app -d rbac` 我一次都没有输过，因为你告诉我 docker 你直接给我，后面再学，导致我心思没有放在这里，所以不能因为我一直用这个跑就当我会了其中的含义而且会用，这又是犯了发之前认为我又会的情况，规定是发知识前一律按我不会处理。**"

## 今天实测（都在 `pg-a3` 上真跑，环境已还原）

1. **`pg_settings` 的 context**：`listen_addresses`/`max_connections`/`shared_buffers`/`wal_level` = **postmaster**（要重启）；`ssl` = **sighup**；`log_min_duration_statement` = **superuser**；`work_mem`/`search_path` = **user**
2. **参数优先级实测**：`ALTER SYSTEM SET work_mem='8MB'` → `source=configuration file`、写进 `auto.conf`；`ALTER ROLE app SET` → `source=user`、**优先级更高**；`SET` → `source=session`
3. **`ALTER SYSTEM cannot run inside a transaction block`**（`psql -c` 多条语句 = 隐式事务）
4. **`pg_hba_file_rules` 7 行**：117 `local all all trust`（他 A3 一直命中这条）／124–126 **`{replication}` 独立于 `{all}`** ← 这就是周六主从复制要撞的墙
5. **缺 schema `USAGE` 报 `relation "users" does not exist`（表在！）** → 加 `USAGE` 后变 `permission denied for table users` → 再加表 `SELECT` 才有数据。**与 11/06「报错指向 A、根因在 B」同族**
6. **`pg_read_all_data` 自带 schema `USAGE`**（`has_schema_privilege=t`）→ 只读账号一行搞定
7. **PG16 `GRANT ... WITH INHERIT FALSE, SET TRUE` 可用**，列名是 `pg_auth_members.inherit_option` / `set_option`（书是 PG15，这条书里没有）
