# 后端全景 · 计划覆盖 vs 剩余缺口（2026-10-26 盘点）

> **用途**：他问"JS 是不是只是一小部分？计划是不是没包括全部？我还差多少才能把后端学完？"
> **明确**：**这份不进计划**，只做"看清家底"的参考。排序与排期仍以 `plan-6months-1017.md` 为准。
> **"学完后端"的界定**（否则这个话题没有边界）：**能独立负责一个中等规模线上服务的后端** —— 能写、能测、能部署、能排查、能讲清取舍。

## 0. 一句话结论

- **JS 基础 = 地基，不是楼层。** 它是"语言层"里的一格，在后端全景里约占 **10%**；没有它下面全塌，但只有它不叫后端。
- 六个月计划覆盖了后端全景的 **约 7 成**（协议 / 数据 / 缓存 / 队列 / AI / 前端 都在里面）。
- **剩余约 30 个工作日**（按 8h/天），其中 **5 块是面试必问、不能拖到计划之后**。

## 3. ⚠️ 时间风险（这是这份表唯一的实际用途）

计划 **2/28 收口 → 3/16 春招**，中间只有 **约 2 周**，装不下 30 天。
所以：**这 30 天不可能全排在计划之后**。要么在 B2/C2 的缓冲里预埋那 5 块（约 13 天），要么接受"春招时只补最必问的"。
**现在不排**，只在 B2 开始前（11/30 Redis 收口时）回来对一次这张表。

## 4. 明确**不学**的（防止被"全能"绑架）

| 项 | 理由 |
|---|---|
| 大数据 / 数仓 / Spark | 除非投相关岗，否则零收益 |
| K8s 深入（Operator/CRD）| 校招只要求"知道概念 + 会 kubectl 基本命令" |
| 分布式事务的落地方案（TCC/Saga 实现）| 概念 + 取舍能讲清就够 |
| 另一门语言（Java/Go）| 校招后端的语言是分叉路；已在 Node 这条上，换语言 = 三个月白扔 |
| DDD / 微服务框架落地 | 没有真实流量时学，只会背名词 |
