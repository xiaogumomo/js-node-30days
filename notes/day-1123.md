## 五、今天的实测数据（全部本机）

### 内存（第 8 章块 A/B）

```
used_memory 3,873,680 / rss 12,021,760  → 3.10
overhead 975,516（其中 startup 948,496）→ 开销占 25.2%
MEMORY STATS: fragmentation 3.12 / allocator-fragmentation 1.06 / allocator-rss 1.80
```

⭐ **纠正昨天那道排查题**：**`rss ≫ used` = 碎片，不是 swap；`rss < used` 才是 swap。**

**淘汰实验（我跑的）**：`maxmemory 2MB + allkeys-lru` → **一条 `SET` 淘汰了 54 个 key**（65→18），`used_memory` 降到 1.52MB。
**`noeviction` 三连**：写 → `OOM command not allowed when used memory > 'maxmemory'.` / 读 → 正常 / **`DEL` → 正常返回 1**。

### 编码阈值（块 C）

```
hash 字段数   512 → listpack  6,200 字节
             513 → hashtable 28,824 字节     ← 4.65 倍
embstr 上限：44 字符（45 就变 raw）
SET 12345 → int（refcount 2147483647 共享）；SET 100000 → int（refcount 1，超 9999 不共享）
```

### ioredis 选项（P2，全部实测）

```
maxRetriesPerRequest:1 → MaxRetriesPerRequestError: Reached the max retries per request limit (which is 1)
enableOfflineQueue:false 断线 → Connection is closed.
commandTimeout:60 + BLPOP 5 → Command timed out (69ms)      ← 客户端放弃，服务端还在等
```

### `keyPrefix` 三个不对称（修正了 11/22 的错）

| 场景 | 加前缀？ | 返回带前缀？ |
|---|---|---|
| `get('pf:a')` | 加 | — |
| **`keys('pf:*')` / `scan(0,'MATCH','pf:*')`** | **不加** | — → 返回 `[]` |
| `keys('p2:dev:pf:*')` | 不再加 | **带** → 要自己剥 |
| **`eval(script,1,'pf:a')`** | **加** | — |
| `eval(script,1,'p2:dev:pf:a')` | **又加一次** → 拿到 `null` | — |
| **`xinfo('GROUPS','p2:dev:mq')`** | **加** → `p2:dev:p2:dev:mq` | — |
