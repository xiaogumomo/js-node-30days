## 三、块① 两半：影响面分析 + 接线实操

### ①-A 影响面分析（他的答案：几乎全填"都会失效"）

**错在方法**：**"都会" = 没做分析**。而且他写"新建了一个 key / 改了一个 key 中的对象" —— **把 DB 的"行"说成 Redis 的"key"**，两层混了。

**正确判据（三条）**：
1. 改哪一行 → 只影响"包含这一行的那几个读接口"
2. **别人的缓存、不包含该字段的接口，一律不动**
3. 统计/总数类缓存要单独考虑（增删会变，改字段不会）

**这张表就是 W5/W6/W7 的来源**：漏列表=W5、漏详情=W6、多删别人=W7。

### ①-B `wire.task.cjs` —— **9/9**

**他踩的 6 个坑，全是"静默失效"**：

| # | 坑 | 类型 |
|---|---|---|
| 1 | **绕过 `getOrLoad` 手写缓存** | 把自造的 5 层防护全拆了 |
| 2 | `db.listByUser` 少 `await` | 忘 await |
| 3 | `cache.set` 存 Promise/对象 → Redis 里是 `[object Promise]`（**16 字符，W1 报 `16 !== 2`**） | 没序列化 |

### ⭐ `loader` 的准确职责（他今天问的）

> **`loader` 是"数据源 → 业务值"的唯一转换点。它的返回值就是将来被缓存的东西。**

**所以凡是"不该让下一个请求看到"的东西，必须在 `loader` 里就挡掉**（归属校验放外面 = 缓存里存了别人的数据，下次命中直接返回，**绕过校验**）。

## 六、第 9 章 · 哨兵（真拓扑实测）

**环境**：1 主 1 从 + **3 哨兵**（quorum=2，`down-after` 3000ms），独立网络 `sntnet`，**不动 `redis-mq`**。

**杀主后的完整时间线（实测，1.24 秒完成）**：

```
+0.000  +sdown master ... 172.20.0.2 6379        ← 主观下线
+0.059  +odown master ... #quorum 2/2            ← 客观下线
+0.059  +try-failover
+0.178  +elected-leader                          ← 选出领头哨兵
+0.231  +failover-state-send-slaveof-noone       ← 给从库发 REPLICAOF NO ONE
+0.332  +failover-state-wait-promotion
+1.150  +promoted-slave                          ← 从库提升完成
+1.240  +switch-master ... → 172.20.0.3 6379     ← 切换广播完成
```

**切换后验证**：新主 `role:master`、可写（`SET after:failover ok` ✓）。

**两个关键判据**：
- **`quorum` 判下线** vs **多数票选领头** —— 是两件事（他答"全票"错了，应为多数 `N/2+1`）
- 哨兵之间靠 **PubSub `__sentinel__:hello`（每 2 秒）** 互相发现，**不写配置文件**

**⚠️ 标"待验"的一条**：重启旧主后 **8 秒内它仍报 `role:master`**（`+convert-to-slave` 还没发生）→ **这段窗口它还能接受写 → 数据会被新主覆盖 → 永久丢失**。所以运维顺序是「确认切换稳定 → 才重启旧主」。

**我踩的坑**：`sentinel monitor` 用**主机名解析失败**（`Can't resolve instance hostname`）→ **必须用 IP**。

## 八、第 4 章 · 客户端（L1）

**抓了真实 RESP 字节**：

```
发送: *2\r\n$3\r\nGET\r\n$13\r\nno-such-key42\r\n
返回: "+PONG\r\n$-1\r\n+OK\r\n"
              └┬─┘
           $-1 = nil
实测对比: $0\r\n\r\n = 空字符串  vs  $-1\r\n = nil  （RESP2 本来就分得清）
```

**我踩的错**：`*2\r\n$4\r\nPING\r\n`（声明 2 个元素只给 1 个）→ `-ERR Protocol error: expected '$', got '*'`
→ **判据：`*N` 的 N 必须等于后面 `$` 的个数。**

⭐ **RESP3 的 `>` Push 类型把 11/22 那个发现解释到协议层了**：订阅消息走独立 Push 通道 → 不再和命令回复抢同一条流 → 所以订阅连接能发普通命令。

**异常 → ioredis 五参数对照**（本章最实用产出）：`connectTimeout` / `commandTimeout` / `maxRetriesPerRequest` / `enableOfflineQueue` / 缓冲区限制。
**架构差异**：Jedis 一请求一连接必须用池；**ioredis 单连接排队，无池** → 瓶颈在单连接串行 → 突破靠 **`pipeline`** 或 **建多个实例**。

**我纠正他的一条**：他说"RESP3 加 `_` 是为了分清空串和 null" —— **RESP2 已经分得清**（`$0` vs `$-1`）。`_` 的真实理由是"**与类型无关的 null**"（能在 map/set/任何位置用，且统一了 `$-1`/`*-1` 两种 null）。
