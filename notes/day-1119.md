## 二、今天最有价值的两组"反直觉"（他自己跑出来的）

### ① Redis 事务**不支持回滚** —— 亲眼看到三次结果

```bash
MULTI
SET lab:tx:c hello        → QUEUED
INCR lab:tx:c             → QUEUED        （字符串不能 INCR）
SET lab:tx:d 已完成        → QUEUED
EXEC
→ 1) OK
  2) (error) ERR value is not an integer or out of range
  3) OK                                   ← 第 3 条照样执行
GET lab:tx:c → "hello"                    ← 第 1 条没被撤销
GET lab:tx:d → "已完成"                    ← 第 3 条已写入
```

**判据**：**Redis 事务只保证"连续执行不被打断"，不保证"出错能撤销"。** 因为**没有 undo log**。

**对照**：入队阶段报错（命令名错）→ **`EXECABORT`，一条都不执行**；运行阶段报错 → **只跳过那一条**。

### ② `WATCH` 是**乐观锁**，不是普通锁

两个窗口实测：A `WATCH` → `MULTI` → `SET`（不 EXEC）；B 改同一 key；A `EXEC` → **`(nil)`**。

**判据**：**`WATCH` 不阻塞别人，只在 `EXEC` 时检查"监视的 key 有没有被改过"；被改过就整个事务放弃，让调用方重试。**

**它正好补上 11/18 Pipeline 那个洞**：Pipeline 管不了"别人插进来"，`WATCH`+`MULTI` 能保证"我读的和写的是同一个版本"。

## 三、Lua 最小集（7 点，我额外补的 —— 书里 3.4.2 假设会 Lua）

| # | 点 |
|---|---|
| 1 | 变量一律 `local`（不加就是全局，污染沙箱） |
| 2 | `if … then … elseif … else … end`（**没有花括号**） |
| 3 | 字符串拼接用 **`..`** |
| 4 | ⭐ **索引从 1 开始**（`KEYS[1]` 是第一个） |
| 5 | `redis.call('GET', KEYS[1])` —— **命令名和参数都用逗号分隔的字符串** |
| 6 | ⭐ **`KEYS` 放要被操作的 key，`ARGV` 放普通值** |
| 7 | 表 = `{}`，长度用 `#arr` |

### ⭐ `EVAL` 的 `numkeys` —— 今天他答偏的地方

```bash
EVAL "脚本" 1 lab:lock mytoken
           ↑ numkeys=1          → KEYS[1]=lab:lock, ARGV[1]=mytoken   ✓
EVAL "脚本" 2 lab:lock mytoken
           ↑ numkeys=2          → KEYS={lab:lock, mytoken}, ARGV={}   ✗
```

**我实测给了对照**：
```
numkeys=1 → KEYS[1]="lab:lock"  KEYS[2]=nil  ARGV[1]="mytoken"  ARGV[2]=nil
numkeys=2 → KEYS[1]="lab:lock"  KEYS[2]="mytoken"  ARGV[1]=nil
```

**判据**：**`numkeys` = "后面有几个参数算 key"，不是"参数总数"。**
**为什么必须分清**：**集群模式下 `KEYS` 里每个 key 都要算槽位** —— 把普通值塞进 `KEYS` 会报 `CROSSSLOT`。

### 锁释放脚本（他现在能读懂了）

```bash
EVAL "if redis.call('get', KEYS[1]) == ARGV[1] then return redis.call('del', KEYS[1]) else return 0 end" 1 lab:lock mytoken
→ 1     （锁是自己的，删掉）
→ 0     （锁没了/不是自己的，什么都不做）
```

**这就是 11/15 那条"释放锁为什么必须用 Lua"的最终落地** —— 因为"读+比较+删"必须在一个原子块里。
