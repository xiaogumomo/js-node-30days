## 三、四组 A/B/A 的结果（他亲手跑的）

### ① RDB：`rdb_saves` 1 → 2

`MSET` 三个 key → `BGSAVE` → 四指标全对：`rdb_saves` 1→2、`rdb_last_bgsave_time_sec:0`、`rdb_changes_since_last_save` 归零、`rdb_last_cow_size:876544`。

⭐ **他一上手就答对了"`LASTSAVE` 不能单独当判据"**：`LASTSAVE` 显示"刚刚"，但 `rdb_saves:0` + `rdb_changes_since_last_save:141872` 才说明"14 万次写从没落过 RDB"。
**这是 11/18 那条"单指标不能当判据"第一次被他自己用出来。**

### ② AOF：`SHUTDOWN NOSAVE` + 重启 = 数据还在

`SET lab:aof:probe v1` → `DBSIZE 31` → `SHUTDOWN NOSAVE` → `docker start` → `GET` = `v1`，`DBSIZE` 还是 **31**。
**答对**："是 AOF 救的"。

### ③ A/B/A 的 B：关掉 AOF → `probe2` 丢了

`CONFIG SET appendonly no` → `SET lab:aof:probe2 v2` → `SHUTDOWN NOSAVE` → 重启 → `probe2` = `(nil)`，`CONFIG GET appendonly` **又变回 `yes`**。

⚠️ **他第一遍答反了**（说"重启时 appendonly 是 no，所以只加载 RDB"）→ **纠正后重答，四步全对**：
> "不是关闭 docker 造成的，是 AOF 没有记录造成的。"

### ④ 重写门槛：74500 倍还没重写

`aof_current_size 6,630,658 / aof_base_size 89` = **约 74500 倍**，`auto-aof-rewrite-percentage` 早满足，但 `aof_rewrites` 还是 **0**。
**他答对了根因**：卡在 **`auto-aof-rewrite-min-size` 64MB** 那道门槛。

→ 顺手立了一条对比：**`save` 的多个条件是"或"，AOF 重写的两个条件是"与"**（正对他"成对的东西只答一半"的弱点）。

`BGREWRITEAOF` 后三条判据全中：`aof_rewrites 0→1`、`base_size = current_size = 689729`、**`appendonly.aof.2.base.rdb` 代数变 2**。

## 五、⭐ 今天新挖出来的三件事（书上没有）

### ① AOF 里一条 `SET` = 43 字节，就是 RESP 原文

```
*3\r\n$3\r\nSET\r\n$12\r\nlab:aof:size\r\n$5\r\nhello\r\n
 4  +   9   +        19        +      11       = 43
```

**顺带纠正他一个算错**：`6630528 − 6630485 = 43`，他把被减数抄成 `6640528` 得出 `10043` —— **"算完不复核"的老毛病**（10/28 的 `/20` 抄错同族）。

### ② 新 incr 文件的**第一条命令前面会自动插一条 `SELECT 0`**（23 字节）

实测：`SET` 之后文件从 **0 → 66 字节** = `SELECT 0`(23) + `SET`(43)。

**为什么必须有**：`INFO keyspace` 显示这台机器有 **db0（31 个 key）和 db2（6 个 key）**。
AOF 是命令流，**不记"当时在哪个库"，重放时全都会落到 db0** → db2 那 6 个 key 就串库了。

### ③ `latest_fork_usec` / COW / 碎片率三个实测

| 指标 | 值 | 含义 |
|---|---|---|
| `latest_fork_usec` | **794**（0.79ms） | 库才 3.8MB → fork 几乎无感 |
| `rdb_last_cow_size` | **876,544** | 库 3.8MB，COW 复制了 **22%** → "内存翻倍"的现实版 |
| `mem_fragmentation_ratio` | **3.15** | RSS 11.89MB vs 逻辑 3.8MB → 删 key + 重写后分配器没还内存（**第 8 章引子**） |
| THP | `always [madvise] never` | 当前 `madvise`；**生产建议 `never`**（COW 粒度 2MB vs 4KB） |
| `maxmemory` | **0** + `noeviction` | ⚠️ 生产危险：满了**拒绝写入**而不是淘汰（第 8 章） |
